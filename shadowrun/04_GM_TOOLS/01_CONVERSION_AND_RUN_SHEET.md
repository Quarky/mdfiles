# GM Run Sheet — Haakonsen-first conversion

## Conversion rule

When a missing 3.5e-era item, program or security feature is needed:

1. Keep its fiction, name and Shadowrun role.
2. Assign a Genesys skill and Action from Haakonsen's list (normally Computers, Mechanics, Skulduggery, Perception or Coordination).
3. Use the access table or an existing Haakonsen item/adversary as the difficulty anchor.
4. Give it a small, explicit effect: one boost/setback, a difficulty shift once, a mark, a trace segment, or a defined damage value.
5. Record whether the item is a **theme conversion** or an exact Haakonsen entry. Never create a Beanstalk-style subsystem to make the item work.

## GM consistency checks

- Do not use “ICE limit” text from the Beanstalk package.
- Do not call a custom program an automatic success; activate it as a Matrix Action and give it the stated cost/effect.
- Do not invent integer damage where the actor/item expects a Genesys damage value. Validate damage as a number before import.
- Keep Matrix marks, physical ownership, and Foundry ownership/permissions separate.
- Player-facing journals should omit trace clocks, secret hosts and NPC motives; GM journals remain owner-only.
