# Network Quick Reference

## Runner turn

1. Activate the intended program before contact if necessary — **maneuver**.
2. Attempt Access to a connected node — **incidental**.
3. If ICE is encountered, immediately Break ICE — **Average Hacking action**.
4. Override strength = net Successes + one compatible active icebreaker. Must exceed ICE strength.
5. If the route is open, Enact one command — **maneuver**.

## Sysop turn

- Unsure anyone is present: **Sweep, Hard Sysops**.
- Intruder known: **Trace, opposed Sysops vs Hacking**.
- Trace sufficient: **Lockout, Formidable minus one step per trace, minimum Easy**.
- Need to harden a route: reactivate ICE — **maneuver**.
- Need to destroy a system or located rig: **Burn System, Daunting Hacking**.

## Timing

- Successful Break ICE suppresses that ICE through the end of the runner’s next turn.
- Attempt Access is incidental but can only trigger an ICE encounter when the runner can immediately take Break ICE.
- Enact Command performs one command; complex tasks can require more than one.
- Activating a program costs one maneuver. Deactivation is free in the current module.

## Blocking defaults

| Type | Default |
|---|---|
| Barrier | Blocks protected subsystem |
| Code gate | Usually ejects or blocks |
| Sentry | Usually does not block; detects, traces, harms, or attacks programs |

## Trace

`0 Formidable → 1 Daunting → 2 Hard → 3 Average → 4 Easy`

## Fast difficulty table

`Simple appliance/public utility → Easy default/public → Average small business/residential → Hard vehicle/police/corporate ops → Daunting government/megacorp → Formidable black site/Beanstalk`

## GM checklist

- Link and access point chosen?
- Base difficulty stated?
- Runner has an action available before ICE contact?
- Correct program active?
- First active ICE layer revealed?
- Total **exceeds** ICE strength?
- Failure effect and blocking state resolved?
- Suppression end recorded?
- Command spent and logged?
- Alert and trace clocks updated?
